02Native

The wallpaper has to slot in between the desktop picture and the desktop icons.

macOS has no “set a live wallpaper” API. What actually works is pinning a borderless window to CGWindowLevelForKey(.desktopIconWindow) − 1 — right above the desktop picture and right below the icons — then making it follow every Space and ignore mouse events. The desktop below is real: flip the switch and watch the wallpaper cross the icon layer.

04Power

When nobody can see it, it doesn’t draw a single frame.

This is where a weekend wallpaper hack and a finished product actually differ. Every pause and throttle decision lives in one governor; the renderers decide nothing on their own — so “why did my wallpaper stop?” always has exactly one answer, and it’s in the log.

live decisions · com.livewall.LiveWall
Screen fully covered by a windowThe biggest win of the lot. Front-to-back window order tells us whether we are really hidden. On by default.
Lock screen / display sleep / system sleepOptional low-latency prewarm keeps only the media pipeline ready while the picture stays paused; system sleep always stops everything.
Low Power ModeFollows the system switch — someone who turns on Low Power Mode wants the background to go quiet.

05Audio reactive

4096-point FFT, 64 logarithmic bands.

Hann window, real FFT, logarithmic banding, peak-decay smoothing — packed into the 128 values a wallpaper page expects. You can pick the input device in Settings, with a live spectrum bar right next to it so you can tell at a glance whether any signal is arriving. Off by default, so nothing asks for microphone access unless you turn it on.

20 Hz200 Hz2 kHz20 kHz
Straight talk: macOS does not let an app capture the sound the system is playing. Without a loopback device like BlackHole, what you capture is the room through your microphone, not the track you are listening to. The feature is complete, but that prerequisite is on you — it is a platform limitation, not an unfinished feature.

09Boundaries

Your desktop shouldn’t become somebody’s cloud asset library.

A live wallpaper can reach a lot of local files, so LiveWall’s default posture is: ask for fewer permissions, keep less data, promise less. What can be done is done properly; what can’t is stated plainly.

Local first.

Wallpapers, bookmarks, import history and diagnostics all stay on your Mac. Nothing is uploaded automatically, and there are no ad-tracking scripts.

Public APIs only.

Desktop window levels, multi-Space behaviour, the power strategy and file access all use documented macOS capabilities, keeping the App Store route open.

Diagnostics you can take with you.

Hit a black screen or a compatibility problem and you can export a redacted local report. It contains state and errors, not your wallpaper files.

No pretend compatibility.

Windows application-type wallpapers and native Scene rendering are not promised. Scene has a legitimate video pre-render path instead.

About this site: this web page uses Cloudflare Web Analytics to count visits. It sets no cookies, does no cross-site tracking, and builds no profile of individual visitors — we only want to know how many people came and where from. The points above describe the app; this one describes the website.

10FAQ

The things you probably want settled before you download.

Is it going to drain my battery?
By default it doesn’t draw a single frame when nobody can see it. A fully covered screen, lock screen, display sleep, system sleep and Low Power Mode each have their own pause reason, with automatic resume on wake; on battery you can pause or lower the frame rate. The optional “Zero-latency unlock (Prewarm)” mode still pauses animation and media, keeping only the video pipeline and web process ready for a faster unlock at the cost of a little extra memory. It never prewarms during system sleep, and the app explains the trade-off before enabling it. Every decision lives in one governor, so “why did my wallpaper stop?” always has exactly one answer — and it’s in the log.
Can I use my own videos or images?
Yes — just drag them into the window. Video: mp4 / mov / m4v (H.264 or HEVC). Images: the usual formats plus GIF. Web wallpapers: HTML / WebGL. webm / VP9 will not play directly and must be transcoded first — AVFoundation cannot decode either codec, which is a platform limitation.
How does it compare to Wallpaper Engine?
Honestly, each has its strengths. It has what we don’t: millions of Workshop items, native Scene rendering, a mature editor. We have what it doesn’t: a different wallpaper per Space (not possible on Windows), automatic switching at sunrise and sunset, and a noticeably more serious power strategy. It also has no macOS version — and the collection you already have can come across with the converter.
macOS blocked the first launch. Is the app broken?
No. This build isn’t notarised by Apple yet — notarisation needs a paid developer account. macOS says it “cannot verify the developer”; open System Settings → Privacy & Security → Security and click “Open Anyway” once. All clicks, no Terminal, and only the first time. Full steps are in the download section.
Does it upload any of my data?
No. Wallpapers, bookmarks, import history and diagnostics all stay on your Mac. Nothing is uploaded automatically and there are no ad-tracking scripts. The only network activity is fetching the wallpaper catalogue index when you refresh it yourself; don’t refresh and it never goes online. Diagnostic reports are exported only when you ask, and contain state and errors, not your wallpaper files.
Which Macs are supported?
macOS 14 or later, on Apple silicon and Intel alike (universal binary). Multiple displays and AirPlay secondary screens have both been tested on real hardware.
Not answered here? This is a beta, and your question is probably somebody else’s too — open an issue and the answer will end up in this section.

macOS will block the first launch — that’s expected

LiveWall is not notarised by Apple yet — notarisation requires a paid Apple Developer account, and there isn’t one yet. So the first launch gets blocked with “cannot verify the developer”. It doesn’t mean anything is wrong with the app. It’s all clicks, no Terminal, and you only do it once:

  1. Double-click LiveWall and let it be refused once. Don’t skip this — the system has to record the block before the “Open Anyway” button appears.
  2. Open System Settings → Privacy & Security.
  3. Scroll down to Security; you’ll see a line saying LiveWall was blocked.
  4. Click Open Anyway next to it, then confirm.

After that it opens normally and never asks again. The same instructions are inside the dmg, in “Read me first.txt”.

If you’d rather use the Terminal, one line does it
xattr -d com.apple.quarantine /Applications/LiveWall.app
Sandbox, privacy manifest, hardened runtime and the login-item capability are all in place, with no private APIs. Shipping on the App Store still needs the Apple Developer Program, proper signing and store assets; notarisation depends on the same account.
